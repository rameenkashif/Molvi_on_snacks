## 6. Design decisions to explain (examiners will ask)
1. **State `(pos, done_mask, flood_left)`** — countdown instead of raw time keeps the space at
   529 × 16 × (F+1). Stolen stops count as done.
2. **Heuristic fix** (MST over {pos}∪R → min d\*(pos,R) + MST(R)) — admissible *and* consistent; proof in docs.
3. **Evaluation features were changed three times because they caused stalling:**
   f1 uses the *exact* static remaining-tour cost (an admissible lower bound made WAIT look best);
   f3 is the *mean* race margin over remaining stops ("next stop" jumped); f4 counts remaining
   ford-dependent stops (a per-cell version flipped between neighbours). This is a good
   "horizon effect / evaluation cliffs" discussion.
4. **Hybrid agent**: A\* plan while the rival is outside the 7×7 window (Chebyshev > 4),
   Alpha-Beta inside; after 3 consecutive WAITs it takes one A\* step (stand-off breaker).
5. **The rival keeps default weights** while the agent is tuned (otherwise tuning changes both players).
6. **Planner replanning triggers:** slip, dam opens, flood ends, a stop is stolen, rival blocks the next cell;
   if the rival stands on a needed stop, plan the other stops first.
7. **Validation layer** — names, stop ids, terrain, step range, structural infeasibility
   (requested stop is of an avoided terrain), unknown arguments; error returned as an observation.
8. **LLM response cache** keyed by sha256(model, system, tools, messages, mode) → reproducible without a key.

## 7. Honest limitations (put in the report)
- The blocker is strong on this map; win rates are low for every agent and CIs overlap, so most
  configuration differences are not statistically significant at n = 30.
- Weight tuning had little effect; the reduced game matters only near the rival.
- IDS cannot solve the 61-action full tour (exponential); reported on 1-stop variants.
- The game search assumes deterministic moves and a 3-ply agent horizon.
- Without stealing the rules let the blocker guard a stop indefinitely.
- Part D results depend on one model (`claude-haiku-5-5`) and one run per request.
